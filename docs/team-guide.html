NeuroDiffusion · for the team

How we work on this project

Each of us owns one experiment, works on it in our own branch, and pushes often so everyone can see progress. Everything on this page runs on a laptop. None of it needs the GPU cluster.

Where things stand

Good newsThere is a real signal. When people imagine one of 33 pictures, a simple method on their brain waves picks the right picture 2 to 3 times more often than random guessing.
The problemOur neural network keeps that signal for only 1 of the 4 people. We are testing why right now.
The limitData. Each person imagined each picture only once, so we have 33 recordings per person. The experiments below either squeeze more out of that or prepare a bigger dataset.

Getting started, step by step

Steps 1 to 4 are a one-time setup. After that it is steps 5 to 8, once per experiment.

01Accept the GitHub invite

Check your email or github.com/JoaoLucasVeras/NeuroDiffusion/invitations. Do this before cloning, or you will not be able to push.

02Clone the project and install

Needs conda.

git clone https://github.com/JoaoLucasVeras/NeuroDiffusion.git
cd NeuroDiffusion
conda env create -f env.yaml
conda activate neurodiffusion
03Get the data

The data is never stored on GitHub. Download the four Imagine_Sub00*.mat files from OSF into datasets/Imagination Experiment/, then run these from the project folder. The image download is about 412 MB, and the split step needs it.

python code/download_stimuli.py
python code/prepare_shimizu_data.py
python code/make_splits.py --dataset datasets/imagination_5_95_std.pth --protocol window --require_images
python code/check_data.py
04Check you match our numbers

Run this. If the bandpower line says top1 0.0985, your setup is identical to ours and you are ready. If not, ask before going further.

cd code
python classical_baseline.py --subject 1 --band 8 13 --skip_eegnet
05Pick an experiment and make your branch

Choose one from the list below and tell Joao, so two people do not take the same one. Name the branch after yourself.

git fetch origin
git checkout -b yourname/band-sweep origin/main
git push -u origin yourname/band-sweep
06Work, and push at the end of every session

Push even when it is unfinished. That is how Joao follows your progress. Add files by name rather than everything at once.

git add code/my_change.py
git commit -m "Add a 30-50 Hz run to the band sweep"
git push
07Open a pull request when you have a result

GitHub shows a button after you push. Fill in the template it gives you, especially “How it was checked” and the numbers.

08Joao reviews and merges

Expect questions about the numbers. That is the review working, not a judgement on your work. Results in this field are easy to misread.

The experiments

Each one is independent, so nobody waits on anyone else. Each answers one question, and each is finished when it produces the table described under “Done when”.

A · band-sweepSmall

Which brain waves carry the signal?

Why it mattersUsing all frequencies scores almost twice as high as the 8–13 Hz alpha band on subject 1. But very low frequencies pick up eye movement, and high ones pick up jaw muscle. If those bands decode well on their own, the extra score is noise from the recording, not imagination.

Start hereNo new code. Run each band below, for every subject.

mkdir ../results
python classical_baseline.py --all_subjects --skip_eegnet --permute 200 --band 1 8 --json ../results/band_1_8.json

Then the same with --band 13 30, --band 30 50, and --band 0 0 for all frequencies, changing the file name each time.

Done whenA table of band by subject, with times-chance and p-value in each cell. Leave it running overnight.

B · ica-cleanupMedium

Does removing blinks with ICA help?

Why it mattersWe tried throwing away noisy recordings, and it did not help. ICA instead repairs a recording by removing just the blink, so we keep it. With only 33 recordings per person, keeping them matters.

Start hereAdd an optional ICA step to prepare() in classical_baseline.py, behind a new --ica flag. Use scikit-learn’s FastICA or MNE. Ask before adding a package to env.yaml.

Done whenThe same permutation test with and without --ica, all four subjects, side by side.

Good fit for Aditya, who found the ICA papers.

C · fewer-choicesMedium

How well can we do with only a few pictures to choose from?

Why it mattersPicking 1 of 33 is hard. The Gao et al. paper reached 75.8% with only 3 categories. A few categories working well would make a realistic first demo.

Start hereAdd a --stimuli option that keeps only the pictures you list, then rerun the baseline. Choose and write down your pictures before running anything. Choosing after seeing results only fools ourselves.

Done whenAccuracy against chance (1 in 3, or 1 in 5) with a p-value, all four subjects.

D · gao-datasetLarge

Get the bigger dataset ready

Why it mattersOurs has 4 people who imagined each picture once. Gao et al. has 22 people with 40 repeats each. It is the only way to learn whether our results hold up for people in general.

Start hereDownload it from figshare and read the paper’s data section. Write a loader that outputs the same fields ours uses (eeg, label, image, subject), then run the baseline on it.

Done whenBaseline numbers with p-values on the new dataset. Its license is non-commercial, so research use only.

Four rules

Stay in your own branch. Everyone can technically push to anyone’s branch, so please don’t push to one with someone else’s name on it.
Never commit data, results or model files. They are large, and removing them later means rewriting history for everyone.
Every result comes with its chance level and a p-value. “9% accuracy” means nothing until you know random guessing gets 3%. Use --permute 200 for the p-value.
Ask before using the cluster. Nothing here needs it, and GPU time is shared.
If a result looks surprisingly good

Be suspicious first and excited second. This field has a long history of exciting results that turned out to be recording noise, and we have already caught one of our own. Post it in the pull request and we will check it together.

Questions go to Joao. The full rules are in CONTRIBUTING.md in the repository.
