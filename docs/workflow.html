NeuroDiffusion

How to work on this project

You can push branches to this repository. You cannot push to main. That one distinction shapes everything below.

One repository, one protected branch

Everyone with access works in the same repository, on their own branch. The permission boundary is not around the repository, it is around main.

The trade-off this makes

GitHub has no per-branch permissions on a personal repository. Anyone with write access can push to, or delete, anyone else’s branch. The naming convention is what prevents that by accident; the platform does not enforce it.

That cost buys something real. The owner sees every branch as it is pushed, rather than seeing finished work only when a pull request appears. For a small team working closely, that visibility is worth more than the isolation a fork would give.

The loop

1Clone the repository, once

Accept the collaborator invitation first. Then clone the project directly, with no second remote to keep in sync.

git clone https://github.com/JoaoLucasVeras/NeuroDiffusion.git
cd NeuroDiffusion
2Set up the environment and data

The data is not in the repository and never will be. docs/DATA.md has the OSF link and the four commands that build the tensors.

conda env create -f env.yaml
conda activate neurodiffusion
python code/check_data.py   # exits non-zero if anything is wrong
3Branch, named after yourself

The yourname/topic convention is what keeps people out of each other’s work, so please keep to it.

git fetch origin
git checkout -b yourname/my-topic origin/main
4Work, and check it against something

The classical baseline is the cheap instrument: five CPU-minutes, and it tells you whether a change helped before anyone spends a GPU-day.

python code/classical_baseline.py --subject 1 --band 8 13 --permute 200
5Push your branch and open the pull request

Pushing makes the work visible to the owner straight away, before it is finished. The printed link opens the pull request against main.

git push -u origin yourname/my-topic

What happens to your pull request

The pull request template asks four things. The third one carries the weight: how it was checked. On this project "ran it" is not checking, because a convincing-looking number is easy to produce and hard to trust.

Reporting a number

Three things travel with every result: its chance level, because 9% is meaningless until you know chance is 3%; its sample size and whether those samples are independent, because twenty windows sliced from one ten-second recording are not twenty measurements; and whether it is a validation or a test figure, because validation numbers are peaks across many attempts and always flatter.

If a result looks surprisingly good, that is a reason for suspicion rather than celebration. This field has a long history of findings that turned out to be recording artifacts, and we have caught one of our own that way.

If you have cluster access

Most of the queue needs no GPU at all. The classical baseline and the small encoder both run on a CPU in minutes, and the project's best current result came out of that lane. Only Stage 2 training needs the SJSU HPC cluster.

If you do have an account, the scripts read two environment variables so they run from anyone's home directory:

export NEURODIFFUSION_ROOT=$HOME/NeuroDiffusion
export NEURODIFFUSION_PYTHON=$HOME/.conda/envs/neurodiffusion/bin/python
